# Exported-surface allowlist (issue #1357, ADR 0029)
#
# Every externally-invokable entry point of the MERGED manifest (app code + all libraries), for
# every shipped flavor x {debug, release}: each effectively-exported component (explicit
# exported="true", or no exported attribute plus an intent-filter) and every <intent-filter>.
# android/app/src/test/.../ExportedSurfaceTest.kt compares this file with the merged manifests
# EXACTLY: a new exported component/filter fails as UNLISTED, a row matching nothing fails as
# STALE. Run by `:app:testObtainiumDebugUnitTest` / `:app:testFossDebugUnitTest` (PR gate).
#
# Row format:  key | flavors | types | reason
#   key      component <tag> <class> permission=<perm|none>
#            filter <class> :: actions=..; categories=..; data=..
#   flavors  * or comma list of obtainium,foss,play      types  * or debug / release
#   reason   REQUIRED. Why this surface is acceptable, in terms of who can invoke it and what
#            guards it. A new entry needs a security review against ADR 0029, not a rubber stamp.
#
# To update: run `cd android && ./gradlew :app:testFossDebugUnitTest --tests '*ExportedSurfaceTest*'`;
# the failure message prints a ready-to-fill row for each UNLISTED item and names each STALE one.
# Prefer removing/narrowing the surface (exported=false, tools:node="remove", a permission) over
# allowlisting it.
#
